# 人物：来源、绑定、表演与口型

> 目标：让角色"像一个在场的人"，而不是一个会移动的剪影。
> 真实感顺序：**表演 > 面部/口型 > 骨骼动作 > 模型精度**。
> 前提：**模型来源决定能力上限**。先按 §1 选路线，再谈表演。

## 1. 角色来源（四选一，按能力排序）

| 路线 | 来源 | 等级上限 | 骨骼 | 表情 | 适合 |
|---|---|---|---|---|---|
| **A 图生 3D** | 三视图 → TRELLIS.2 / Hunyuan3D-2.1 → 重拓扑 → UniRig | T3 | 自动，需校 | 需自建 blendshape | 独特造型、写实主角 |
| **B VRM** | VRoid Studio / Ready Player Me | T2 | 自带 Humanoid ≥50 | 自带（happy/angry/sad/blink 等） | 最快、最稳、动漫/半写实 |
| **C 商业/CC0 人形** | Mixamo 角色、CC0 扫描、商店模型 | T2–T3 | 自带或 Mixamo | 看资产 | 配角、群像 |
| **D 程序化** | 参数化几何 + 微动作 | T1 | 父子节点 | 无 | 只允许剪影/远景/风格化 |

**VRM 是备选，不是默认。** 它的优势是"开箱即用"：人形骨骼、表情、lookAt、口型接口全部标准化，一天能出片。劣势是脸型偏动漫，做真实人脸特写会露怯。

**路线选择决策**

```text
角色要做 CU/ECU 吗？
├─ 要，且必须写实 → 路线 A（图生 3D + UniRig + 4K 皮肤），或混合方案（人脸走视频生成）
├─ 要，但可以风格化 → 路线 B（VRM，最高性价比）
└─ 不要（只到 MCU 或更远）→ 路线 B/C 均可；群像用 C + Instancing
```

**一致性三件套**：唯一实例（全片只加载一次）+ 三视图/设定板锁定 + 同一光照/LUT。

## 2. 各路线的最小可用配置

| 项 | 路线 A（T3） | 路线 B（VRM，T2） | 路线 C（T2） | 路线 D（T1） |
|---|---|---|---|---|
| 三角面 | ≤120k | ≤60k | ≤60k | ≤15k |
| 骨骼 | ≥55 | ≥50（Humanoid） | ≥30 | 父子节点 |
| 手指 | 15 骨 | 15 骨（VRM 有） | 看资产 | 无 |
| blendshape | ≥15（自建） | 自带 5–8 组 | 看资产 | 无 |
| 贴图 | 4K 皮肤 + 2K 服装 | 2K 内置 | 2K | 纯色 |
| 口型 | viseme → blendshape | viseme → VRM expression | 下颌骨 | 不开口 |
| 最大画幅 | CU/ECU | MCU | MCU | MS |

**T3 自建 blendshape 最小集**（15 个）：`blink_L`、`blink_R`、`browDown`、`browUp`、`smile`、`frown`、`mouthOpen`、`mouthWide`、`mouthPucker`、`jawLeft`、`jawRight`、`cheekPuff`、`noseSneer`、`eyeLookUp`、`eyeLookDown`。

## 3. 骨骼与动作

- 人形骨骼 ≥30 根；手指 15 根（MCU 以内才需要）。
- **足部 IK**：地面/甲板高度变化时脚不滑；重心随坡度调整。
- **手部 IK**：扶栏杆、端杯、握工具——手必须真的"贴"在物体上。
- **重定向**：Mixamo → Humanoid 需要映射；`three-vrm` 有 humanoid 接口，可直接吃 VRM。
- **动作库**：走/跑/蹲/爬/坐/转身/挥手/扶额；每场至少一个"非循环"动作。

### 纯函数约束（必须）

```js
// ❌ mixer.update(dt) 会让 seek 漂移
// ✅ 绝对时间
mixer.setTime(t - clipStart);

// 程序化叠加（呼吸/重心）仍用 t
crew.position.y = baseY + Math.sin(t * 1.15 + phase) * 0.012;
```

## 4. 面部与表情

- **blendshape**：ARKit 52 维；VRM 用内置表情（happy/angry/sad/relaxed/surprised/blink）。
- **微表情**：眉毛 0.1–0.2 权重、嘴角 0.05–0.1、眨眼每 3–6 秒一次（固定 seed）。
- **眼神**：VRM `lookAt` 指向目标；对话时看对方眼睛，思考时看向画外。
- 恐怖片里"面无表情"是表演：**只给眨眼和呼吸，不给表情**，比狰狞更可怕。

### 表情分级（按资产等级）

| 等级 | 可用的表情 | 禁止 |
|---|---|---|
| T3 | 全脸微表情 + 口型 + 眼神 | — |
| T2（VRM） | 内置表情 + 眨眼 + 口型 | 复杂情绪（哭/怒的细节） |
| T1 | 眨眼 + 头部朝向 | 任何面部特写 |
| T0 | 无 | 进成片 |

## 5. 口型（viseme）

| 路线 | 工具 | 说明 |
|---|---|---|
| 离线预处理 | `rhubarb-lip-sync` CLI | 音频 → viseme 时间轴 JSON；浏览器只查表，最稳 |
| 浏览器内 | `met4citizen/HeadTTS` | Kokoro TTS + 时间戳 + viseme |
| 运行时 | `met4citizen/TalkingHead` | 现成口型/姿态 |
| 精细对齐 | WhisperX / stable-ts | 词级时间戳，用于逐词口型与字幕 |

- 8 个基础口型（A/E/I/O/U/M/F/L），权重做 60–120ms 平滑，避免"机械嘴"。
- **协同发音**：相邻音素互相影响，不能一个音一个硬切。
- 对齐误差目标：**≤80ms**（人眼可察觉阈值约 100ms）。

```js
// 按绝对时间查表，seek 可复现
const w = visemeAt(t - line.start);
for (const [name, v] of Object.entries(w)) {
  const i = mesh.morphTargetDictionary[name];
  if (i != null) mesh.morphTargetInfluences[i] = v;
}
```

## 6. 二次动作（"活着"的关键）

| 动作 | 幅度 | 频率 |
|---|---|---|
| 呼吸 | 胸/肩 ±0.01–0.02m | 0.2–0.3Hz |
| 重心 | 躯干 ±1–2° | 0.1–0.2Hz |
| 头部环视 | ±5–10° | 0.05–0.15Hz |
| 眨眼 | 0→1→0，80ms | 3–6s |
| 手指微动 | ±2–4° | 0.3Hz |
| 布料/头发 | 物理或顶点动画 | 跟随运动 |

**没有二次动作的角色 = 假人**。哪怕只有呼吸和眨眼，观感也会提升一个档次。

## 7. 表演方法（导演层面）

- **目标—障碍—动作**：每个角色在每个场景都要有"想要什么"和"被什么挡住"。
- **情绪节拍**：一场戏 3–5 个节拍，每个节拍情绪转一次；不要一条情绪演到底。
- **停顿**：对白之间的停顿比台词更能演；停顿处给反应镜头。
- **身体先于台词**：先有动作，再开口；观众先信身体。
- **视点**：谁在看、看哪里、看到了什么——决定剪辑。
- **画幅自保**：当角色等级不足以支撑 CU 时，用背影、手部、物件、剪影、反应镜头替代，不要硬切特写。

## 8. 预算与验收

| 项 | 桌面 | 集显 |
|---|---|---|
| 骨骼/角色 | ≤80 | ≤30 |
| blendshape | ≤52 | ≤16 |
| 同屏角色 | ≤12 | ≤6 |
| 三角面/角色 | ≤120k（T3）/ ≤60k（T2） | ≤15k |

验收：
- [ ] 口型对齐误差 ≤80ms
- [ ] 脚不滑、手不穿模、道具不"贴"在空气上
- [ ] 每 3–6 秒有眨眼，静立时有呼吸
- [ ] 说话时有头部微动，不是"木头人"
- [ ] 同一角色跨镜同一实例、同一材质、同一光照
- [ ] 角色画幅不超其等级上限（T1 ≤MS、T2 ≤MCU、T3 不限）
- [ ] 肘/膝弯曲无塌陷；手指能抓握
